# 贾维斯主题重构方案 —— 结构整理 · 视觉零 diff

> 依据 2026-10-20 对当前代码的实测盘点（数字均为 `Select-String` 全库统计）。
> 性质：**纯结构重构，不改变任何像素**。贾维斯 HUD 风格保持 1:1 还原（既有决定 m1141d）。
> 原则：每阶段一个 commit、独立可验证、可单独回滚；全程以「重构前后截图 + computed style 对拍 = 零差异」为硬验收。

---

## 0. 结论摘要

贾维斯主题当前散落在 **25 个文件、252+ 处** `[data-theme='jarvis']` 选择器里，其中 **154 处**硬编码 `rgba(34, 211, 238, X)`（电光青），另有一批零散硬编码深底色。改一个颜色要动 25 个文件；加第三套主题等于把这一切再做一遍。还发现一处真实不一致：窗口底色上报 `#071018`，CSS `--bg` 却是 `#060b14`，启动瞬间存在色差。

重构四步（详见 §6）：

1. **令牌化**：所有硬编码色值收敛到 `styles/tokens.css` 的 CSS 变量（唯一改色处），透明度梯度用 `color-mix()` 表达，一套规则服务全部主题；
2. **分层归位**：颜色「参数差异」并入主题无关的基础层（A 类，预计消化约六成 jarvis 规则），「结构装饰」（角括号/扫描线/等宽遥测/网格背景）保留 `[data-theme='jarvis']` 前缀并集中（B 类）；
3. **三源合一**：CSS 变量、xterm JS 色板、主进程窗口底色统一由 `shared/theme-tokens.ts` 单源派生，顺带修掉 `#071018/#060b14` 不一致；
4. **全程零 diff 验证**：CDP 截图 + `getComputedStyle` 对拍，每个阶段收尾跑 typecheck / test / build。

收益：改色只动 1 个文件；`data-theme='jarvis'` 前缀从 219 处降到 ~80 处以内（只剩真正的结构装饰）；加新主题的成本降为「一段 `:root` 变量 +（可选）一份结构变体」。

## 2. 目标与非目标

**目标**

- G1 改色收敛：全库改一处（`tokens.css`）即可调整主题色/底色/梯度。
- G2 规则主题无关化：能用变量表达差异的规则只写一份，两套（将来多套）主题自动适配。
- G3 三源合一：CSS 变量、xterm 色板、窗口底色单源。
- G4 可扩展：新增第三套主题 = 加一段 `:root` 变量（+ 可选结构变体文件）。
- G5 视觉零 diff：重构前后截图与 computed style 对拍一致。

**非目标（明确不做）**

- 不改任何视觉表现（颜色、透明度、字号、装饰均保持现值）；
- 不改组件 DOM 结构与类名（`edit_file` 迁移时类名以源码为准）；
- 不引入 SCSS/Less/Tailwind/CSS-in-JS——保持纯 CSS，仅用原生 `color-mix()`（Chromium ≥111）与原生 CSS Nesting（Chromium ≥112；本项目 Electron 44 远高于此）；
- 不动主题应用时序：`main.ts` 挂载前 `applyTheme` 仍是唯一入口（既有经验 m45282）。

## 3. 目标架构

### 3.1 文件结构

```
src/renderer/src/
  styles/
    tokens.css      # L0 令牌层：三套 :root 变量（浅/深/jarvis）——全库唯一改色处
    base.css        # L1 基础层：主题无关的元素/通用小件规则，全部走变量
    jarvis.css      # L2 贾维斯结构装饰层：角括号/扫描线/网格背景/等宽遥测/发光环（自根目录迁入）
    main.css        # 入口：@import 上面三个；main.ts 只引这一个
  components/…      # L3 组件 scoped：只留「结构性装饰」，写法收敛（见 3.3），色值一律引用令牌
src/shared/
  theme-tokens.ts   # L4 单源常量：JARVIS_BG / SYSTEM_BG(dark,light) / XTERM_JARVIS 色板
                    #    —— theme.ts 上报底色、TerminalCard 色板都从这里 import；
                    #    tokens.css 中对应变量用注释锚点互指（值以 TS 为准还是 CSS 为准见 §5.3）
```

`App.vue`、`desktop/JarvisHUD.vue`、`JarvisTelemetry.vue` 属于「桌面壳结构装饰」，保留在组件内，同样只做色值令牌化。

### 3.2 规则二分法（迁移的判断标准）

每条现存 jarvis 规则归入两类：

- **A 类 · 参数差异**：主题间只是**值不同**（底色、边框色、hover 底、选中底、辉光强度、圆角…）。
  → 提升为变量，规则并入 `base.css` 的通用选择器，**删除 jarvis 前缀**。
  例：输入框 `background: rgba(34,211,238,0.04)` → `background: var(--input-bg)`，浅色主题给 `--input-bg` 白玻璃值。
- **B 类 · 结构装饰**：jarvis **独有**的形态（有没有的问题）：四角括号、扫描线动画、全息网格背景、等宽遥测文案（`--font-hud` 应用）、HUD 头像环、uppercase+letter-spacing 标题…
  → 保留 `[data-theme='jarvis']` 前缀；全局的进 `styles/jarvis.css`，组件专属的留 scoped。

预估：A 类约占全部 jarvis 规则的 **60%**（219 处前缀最终剩 ~80 处）。

### 3.3 组件 scoped 写法收敛

现状每个组件平铺 N 条 `[data-theme='jarvis'] .xxx { … }`。收敛为原生嵌套：

```css
/* Composer.vue <style scoped> 内，现状： */
[data-theme='jarvis'] .composer-card { background: rgba(13, 30, 52, 0.35); … }

/* 收敛后：A 类参数直接并入 .composer-card 主体规则（用变量）；
   B 类结构装饰嵌套进对应选择器： */
.composer-card {
  background: var(--panel-input);            /* A 类：变量驱动，双主题自适应 */
  [data-theme='jarvis'] & {
    box-shadow: 0 0 18px var(--glow-soft);   /* B 类：装饰保留、色值令牌化 */
  }
}
```

> 风险控制：嵌套写法在阶段 3 的第一批（Composer.vue）先试点，typecheck + 截图对拍通过后再推广；万一 SFC 编译器行为异常，退回平铺写法（仅色值令牌化），不影响整体方案。

### 3.4 透明度梯度：`color-mix()` 方案

154 处 `rgba(34, 211, 238, X)` 不逐一建变量（会爆炸），而是：

```css
/* tokens.css */
:root { --accent-glow-weak: color-mix(in srgb, var(--accent) 8%, transparent); }
:root[data-theme='jarvis'] { --accent: #22d3ee; /* 只改基色，梯度自动跟随 */ }
```

- 同一语义档位才共用一个梯度变量；**不同语义即使数值相同也不共用**（避免改 A 处意外影响 B 处）；
- 迁移时逐一对映现值（0.04→4%），**禁止就近取整**（低透明度装饰本就处在「看得见/看不见」的临界区，教训 mf9364：25% 的青看着像系统灰）。

## 5. 三源合一（CSS / xterm / 主进程底色）

### 5.1 现状三源

1. CSS：`style.css` `:root[data-theme='jarvis']` 变量表；
2. xterm：`TerminalCard.vue` `XTERM_THEMES.jarvis`（18 色 JS 对象，含 `cursorAccent: '#071018'`）；
3. 主进程：`theme.ts` 硬编码 `#071018` 上报 → `preload` → `bridge.ts setBackgroundColor`。

### 5.2 目标

`src/shared/theme-tokens.ts` 为**唯一真相**：

```ts
export const THEME_BG = {
  system: { dark: '#1e1f22', light: '#f6f6f7' },
  jarvis: '#060b14',            // 修 P0：与 CSS --bg 统一（统一到 #060b14，以 CSS 现值为准）
} as const
export const XTERM_THEMES = { system: {…}, jarvis: {…} }   // 自 TerminalCard.vue 迁入，值不变
```

- `theme.ts` 上报底色、`TerminalCard.vue` 色板改 import；CSS `tokens.css` 的 `--bg`/xterm 底色以注释锚点 `/* = THEME_BG.jarvis */` 互指（构建期生成 CSS 属过度设计，不做）；
- 修复 P0：启动窗口底色与 `--bg` 完全一致，消除启动瞬间色差。

### 5.3 保持不动的既有机制（有历史教训，勿「顺手优化」）

- `main.ts` 挂载前 `applyTheme(loadTheme())` 唯一入口（m45282：两处应用会首帧闪系统样式）；
- xterm 隐藏输入框排除：`:not(.xterm-helper-textarea)` 必须保留；
- xterm 主题支持热切换（`uiTheme` 响应式订阅）保持现状；
- 切主题 IPC 上报即时生效（me07b6）。

## 8. 验收标准

1. 全库 `data-theme='jarvis'` 前缀 ≤ 90 处（A 类规则并入基础层后的 B 类残量）；
2. `rgba(34, 211, 238` 全库硬编码 = 0（仅 `tokens.css` 定义 `--accent` 一处 + `theme-tokens.ts` 一处）；
3. 修改 `tokens.css` 中 `--accent` 单值 → 两主题下全部跟随色同步变化（演示脚本断言）；
4. 窗口底色 = `--bg`（`getComputedStyle(document.documentElement).getPropertyValue('--bg')` 与上报值一致）；
5. `npm run typecheck` / `npm test` / `npm run build` 全绿；
6. 重构前后各窗口截图 + computed style 对拍零差异（抗锯齿级像素差异除外）；
