# 客户端设备：让服务端用上客户端机器连的硬件（device.* 协议 v1，第二版）

> 状态：客户端（本仓库）、Friday（`qt/src/core/remote/ClientDevices`，v2.78）、Friday.Powers 的 **devices** 能力都已实现。
> 服务端那一侧的权威说明在 Friday 的 `qt/docs/REMOTE.md` §6「客户端设备」和 Friday.Powers 的 `docs/devices-protocol.md`；
> 这里是客户端要做的全部：反向请求的参数、结果、授权、专用通道。

## 1. 要解决什么

硬件插在客户端这台电脑上，服务端（Agent 和它跑的程序）在远端：

| 设备 | 服务端怎么用 | 客户端这头 |
|---|---|---|
| 串口开发板（ESP / Arduino / STM32 / 任意 USB 转串口） | `rfc2217://127.0.0.1:<port>`：esptool、pyserial、PlatformIO、idf.py 直接用 | WebSerial；客户端是 RFC 2217 服务器 |
| ESP 烧录 | `client__flash` method=esp | esptool-js（Espressif 官方网页烧录器同款），本机速度 |
| UF2 板子（树莓派 Pico、Adafruit 的 nRF52 / SAMD……） | `client__flash` method=uf2 | 主进程往 UF2 盘里写 .uf2 |
| Arduino（Uno / Nano / Pro Mini，optiboot） | `client__flash` method=stk500（.hex / .bin） | WebSerial 上的 STK500v1 |
| STM32（串口引导） | `client__flash` method=stm32 | WebSerial 上的 AN3155，8E1 |
| 摄像头 | `client__camera_snapshot`（MCP 图片） | getUserMedia → canvas |
| 安卓手机 | `ADB_SERVER_SOCKET=tcp:127.0.0.1:<port>` 后照常用 adb | 隧道到本机 adb server，**只放行授权的那一台** |
| iOS 设备 | `USBMUXD_SOCKET_ADDRESS=127.0.0.1:<port>` 后用 libimobiledevice | 隧道到本机 usbmuxd |
| 局域网设备（树莓派 SSH、网络摄像头、Modbus TCP……）、客户端本机的服务（openocd 3333） | TCP 隧道 `127.0.0.1:<port>` | 协议进程开 socket，只通本机 / 局域网地址 |
| 原厂烧录 / 调试工具（avrdude、openocd、st-flash、picotool……） | `client__run_tool` | 主进程跑白名单里的程序，**每次都问** |

为什么串口不用 pty：esptool 烧录要拉 DTR/RTS 让芯片复位进下载模式、中途改波特率，pty 都传不过去；RFC 2217 都带在流里。
为什么烧录放客户端：隔着公网走 RFC 2217，每块都要一个来回，走 TURN 时又慢又容易超时；本机烧和插在本机上一样快（RFC 2217 烧录照样可用）。

## 2. 能力声明（hello）

```jsonc
"features": ["messagePatch", "clientDevices"],
"clientDevices": { "version": 1, "kinds": ["serial", "esp.flash", "camera", "tcp", "android", "ios", "flash.uf2", "flash.stk500", "flash.stm32", "tool"] }
```

没声明的客户端，服务端不发 `device.*`。服务端的 `server.features` 有 `clientDevices` 才接得住；`server.clientDevices.power` 是它装没装 devices 能力
（「设备」窗口据此提示）。

## 3. 反向请求（服务端 → 客户端）

同一条 `friday-work` 通道上，服务端发 `{"jsonrpc":"2.0","id":"s:17","method":"device.…","params":{…}}`，客户端按 id 回 `result` / `error`。
只认 `device.` 开头的，其余回 `-32601`。大消息照旧走 WorkFramer 分片（单条上限 64 MB）：固件、照片直接 base64 放在 JSON 里。

错误码：`-32601` / `-32602`，`20` 用户拒绝（或 60 秒没理）、`21` 设备不存在 / 已拔掉、`22` 设备忙、`23` 操作失败（`message` 里有原因）。

客户端发的通知（没有 id）：`device.changed`、`device.serial.closed {sessionId, reason}`、`device.tcp.closed {sessionId, reason}`、
`device.esp.progress` / `device.flash.progress {requestId, token, fileIndex, written, total}`（`token` = 请求里的 `progressToken`）、
`device.tool.exited {runId, exitCode, output}`。

## 4. 授权

第一次被某台机器要用某样设备时弹窗：**允许这次 / 始终允许 / 拒绝**，60 秒没人点 = 拒绝（`20`）。

| 能力 | 什么算一样设备 | 能「始终允许」 |
|---|---|---|
| 串口 | 那个串口 | ✓ |
| 烧录（ESP / UF2 / Arduino / STM32、读芯片） | 那个串口 / 那个 UF2 盘 | ✓ |
| 摄像头 | 那个摄像头 | ✓ |
| 局域网连接 | `host:port` | ✓ |
| 安卓手机 | 那台手机 | ✓ |
| iOS 设备 | 这台电脑的 usbmuxd（所有 iOS 设备） | ✓ |
| 运行工具 | 每一次 | ✗ 每次都问，弹窗里写完整命令 |

「始终允许」按 机器 × 能力 × 设备 记在这台电脑上，「设备」窗口和设置里都能撤销。使用中的设备在桌面上常亮一条，串口、隧道、后台工具可一键断开。
`device.list` 不弹窗。

## 5. 方法

### 5.1 `device.list` → `{devices: [...]}`

| kind | id | 其他字段 |
|---|---|---|
| serial | `serial:<vid>:<pid>:<n>` | `label`（COM5 · CP210x）、`portName`、`usbVendorId` / `usbProductId`、`espHint` |
| camera | `camera:<deviceId>` | `label` |
| android | `android:<序列号>` | `label`（Pixel 8（R5CT））、`state`（device / unauthorized / offline） |
| ios | `ios:<UDID>` | `label`、`state`（USB / Network） |
| uf2 | `uf2:<盘的根目录>` | `label`（RP2040（E:））、`model`、`boardId` |

手机是协议进程直接问本机的 adb server（`host:devices-l`）和 usbmuxd（`ListDevices`）得到的，不起外部程序；UF2 盘是主进程找根目录下有
`INFO_UF2.TXT` 的盘。设备增减（WebSerial connect / disconnect、摄像头 devicechange）时发 `device.changed`。

### 5.2 串口：`device.serial.open` / `device.serial.close`

```jsonc
// open
{ "deviceId": "serial:…", "mode": "rfc2217", "baudRate": 115200, "dataBits": 8, "parity": "none", "stopBits": 1 }
// → DataChannel 打开之后才回
{ "sessionId": "k3v9x2", "channel": "friday-serial:k3v9x2" }
// close
{ "sessionId": "k3v9x2" }
```

在同一个 PeerConnection 上 `createDataChannel("friday-serial:<id>")`，上面全是二进制消息：`rfc2217` 模式是 RFC 2217 的 Telnet 流
（客户端是服务器，IAC 双写），`raw` 是原始字节。支持：`BINARY` / `SGA` / `COM-PORT-OPTION` 协商，`SIGNATURE`、`SET-BAUDRATE`（关口按新波特率重开、
补回 DTR/RTS）、`SET-DATASIZE` / `PARITY` / `STOPSIZE`（7/8 位、无/奇/偶、1/2 位）、`SET-CONTROL`（DTR、RTS、BREAK、流控）、`NOTIFY-MODEMSTATE`、
掩码、`PURGE-DATA`、`FLOWCONTROL-SUSPEND/RESUME`。控制命令和数据严格按流里的顺序执行（复位时序靠这个）。同一个口同时只有一个会话（`22`）。

### 5.3 ESP：`device.esp.flash` / `device.esp.info`

```jsonc
{ "deviceId": "serial:…", "files": [{ "address": "0x10000", "data": "<base64>" }], "baudRate": 460800,
  "flashMode": "keep", "flashFreq": "keep", "flashSize": "keep", "eraseAll": false, "compress": true,
  "before": "default_reset", "after": "hard_reset", "progressToken": "job-3" }
// → { "chip": "ESP32-S3 …", "files": [{ "address": 65536, "size": 912384, "md5": "…" }], "elapsedMs": 9234, "log": "…" }
```

每个文件烧完比对 flash MD5。这个口开着串口会话时先挂起（口让给烧录、通道不关、进来的字节攒着），烧完按原参数恢复——服务端的串口监视
直接看到新固件的启动日志。`device.esp.info {deviceId, before}` → `{chip, features, mac, flashSize}`，读完复位回应用。

### 5.4 摄像头：`device.camera.snapshot`

`{deviceId?, width?, height?, format?: jpeg|png, quality?: 0.85, warmupMs?: 600}` →
`{mime, data(base64), width, height, deviceId, label, takenAt}`。拍完立刻关掉轨道。

### 5.5 TCP 隧道：`device.tcp.open` / `device.tcp.close`

```jsonc
{ "host": "192.168.1.50", "port": 22 }                 // 局域网 / 本机的 host:port
{ "service": "adb", "deviceId": "android:R5CT" }        // 本机 adb server，只放行这一台
{ "service": "usbmux" }                                 // 本机 usbmuxd（Windows 127.0.0.1:27015，其余 /var/run/usbmuxd）
// → { "sessionId": "…", "channel": "friday-tcp:…" }
```

DataChannel 在渲染进程、socket 在协议进程（渲染进程开不了 TCP），字节经数据面端口搬（`tunnel.*` 消息）；通道积压超过 1 MB 时 socket 暂停读。
`host` 先解析，解析出的地址必须全是本机 / 私有网段 / 链路本地 / CGNAT，否则拒绝。

**adb 过滤**（`protocol/device/AdbGate`）：看 adb 主机协议（4 位十六进制长度 + 文字）——`host:version` / `features` / `list-forward` 照转；
`devices[-l]`、`track-devices[-l]` 的回复只留这一台；`host:transport[-any|-usb|-local]`、`host:tport:{any,usb,local}` 改写成这一台，别的序列号拒绝；
`host-usb:` / `host-local:` / `host:get-*` 改写成 `host-serial:<它>:`；`kill`、`connect`、`disconnect`、`pair`、`reconnect` 一律拒绝
（不让服务端关掉客户端的 adb server、连别的手机）。切到手机之后的字节（shell、sync、install……）不再管。两边 adb 版本要一致：
服务端的 adb 发现版本对不上会发 `host:kill`，被拒绝后报错。

### 5.6 别的烧录：`device.flash`

```jsonc
{ "deviceId": "uf2:E:\\" | "serial:…", "method": "uf2" | "stk500" | "stm32", "data": "<base64>", "format": "bin" | "hex",
  "address": "0x08000000", "baudRate": 115200, "pageSize": 128, "reset": "none" | "dtr-rts", "progressToken": "job-4" }
```

- **uf2**：主进程只往根目录有 `INFO_UF2.TXT` 的盘写、只写真的 UF2 镜像（每 512 字节一块、三个魔数都对），文件名固定 `firmware.uf2`。
- **stk500**（Arduino optiboot，同 avrdude `-c arduino`）：DTR/RTS 拉低 250 ms 再拉高 → `GET_SYNC`（重试 10 次）→ 读签名 → 按页写 → 逐页读回核对 → 退出编程模式。
  缺省 115200（老 bootloader 的 Nano 57600）、页 128 字节。Mega 2560 是 STK500v2，用 `run_tool` 跑 avrdude。
- **stm32**（AN3155，8 位偶校验，缺省 57600）：`0x7F` → GET（扩展擦除还是普通擦除）→ GET ID → 整片擦除 → 每块 256 字节写 → 读回核对 → GO。
  要先让芯片从系统存储器启动（BOOT0 拉高再复位）；`reset: dtr-rts` 时用 RTS 拉 BOOT0、DTR 拉 NRST。
- `format: hex` 时先展开 Intel HEX（空洞填 0xFF），起始地址取 HEX 里的最低地址。
- 同 ESP：开着串口会话的口先挂起、烧完恢复。

### 5.7 本机工具：`device.tool.run` / `device.tool.stop`

```jsonc
{ "tool": "avrdude", "args": ["-p", "m2560", "-c", "wiring", "-P", "COM7", "-U", "flash:w:{file:fw.hex}:i"],
  "files": [{ "name": "fw.hex", "data": "<base64>" }], "background": false, "timeoutMs": 300000 }
// 前台 → { "exitCode": 0, "output": "…（末尾 64 KB）", "elapsedMs": 4100, "command": "avrdude …" }
// 后台 → { "runId": "a1b2c3d4", "command": "openocd …" }；结束时发 device.tool.exited
```

白名单：avrdude、openocd、st-flash、st-info、stm32flash、STM32_Programmer_CLI、picotool、dfu-util、nrfjprog、JLinkExe、JLink、esptool。
在 PATH 里找（Windows 只认 .exe：.cmd / .bat 要经 shell，参数会被再解释一遍）；不经 shell，参数原样给；文件放进这次专用的临时目录，
参数里 `{file:名字}` 换成它的路径、`{dir}` 换成目录；跑完删掉。后台的（openocd 当 GDB 服务）用 `device.tool.stop {runId}` 停，
服务端再用 TCP 隧道连 `127.0.0.1:3333`。

## 6. 服务端那一侧（已实现）

- **Friday**（v2.78）：`RemoteServer` 认 hello 里的 `clientDevices`、发反向请求（`"s:N"`）、配回复 / 超时 / 断开；`RemoteWorkSession` 接
  `friday-serial:*` / `friday-tcp:*` 专用通道；`ClientDevices` 只中转：有这样的客户端连着、devices 能力装好开着时拉起它、经 `/v1/bridge` 交给它。
- **devices 能力**（Friday.Powers）：开本机端口（rfc2217 / adb / usbmux / TCP 隧道），读服务端本机的固件文件，以 MCP 服务 `client` 给智能体工具：
  `devices`、`serial_open`、`tunnel_open`、`android_attach`、`ios_attach`、`ports`、`port_close`、`flash`、`esp_info`、`camera_snapshot`、
  `run_tool`、`stop_tool`、`job_wait`。烧录、跑工具这种慢的超过 100 秒先回 job_id。

## 7. 安全

- 服务端只能拿到客户端上的人授权过的设备；授权按机器分开记，随时可撤销；跑工具每次都问。
- TCP 隧道只通本机和局域网；adb 只放行一台手机、不让关 server；UF2 只写到 UF2 盘、只写 UF2 镜像；工具只认白名单、不经 shell。
- 摄像头每次拍照都是一个请求，「这次」授权只管这一张。
