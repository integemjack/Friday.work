# 方案：克隆声音并应用到当前 TTS（CosyVoice3 / friday-voice）

> 2026-10-22。目标：用户在客户端里录一段自己的声音，助手播报（TTS）就能用这个声音说话。
> 全程本地（GPU 引擎）处理，不上传。前置事实均已核实（代码/协议/上游仓库），出处见文末。

## 一、结论（TL;DR）

**可行，且链路几乎全是现成的——缺的只有一环：引擎把上游的 ONNX 前端裁掉了。**

当前 TTS 用 CosyVoice3 的「预生成音色」模式：`voices/*.gguf` 是参考录音离线提好的
prompt_speech（语音 token + 说话人向量 + 底稿文字）。音色文件的上游生成工具
（speech tokenizer + campplus 两个 ONNX）在 Friday.Powers 编译时被**有意裁掉**
（voice/CMakeLists.txt 注释：「音色 prompt_speech.gguf 离线生成好随模型下载」）。

所以要做的核心只有一件事：**给 friday-voice 引擎（v0.5.0）把前端编回来，加一个
克隆入口（CLI 子命令 + serve HTTP 端点）**；客户端加「克隆向导」UI 和按需下载。
预估：引擎 1.5–2 天 + 客户端 1–1.5 天 + 实测 0.5 天。

## 二、现状与差距（为什么现在不能克隆）

| 环节 | 现状 | 克隆需要 |
|---|---|---|
| 音色加载 | Synthesizer::load() 启动时扫一遍 `voices/*.gguf`（`cosyvoice_prompt_speech_load_from_file`） | ✅ 已有；需加**热注册**（不重启加新音色） |
| 音色生成 | 无。引擎 `--help` 只有 serve/transcribe/speak/speaker/merge/info；协议里也没有造音色的端点 | ❌ **缺**：ONNX 前端（speech tokenizer + campplus） |
| 声纹提取 | 有，但用途不同：`speaker` 子命令/`POST /v1/audio/speaker` 出 192 维向量，用于「只听我说」过滤 | ⚠️ 可复用同一份 campplus.onnx 权重文件，但 TTS 前端走 ORT 加载 |
| 底稿文字（prompt-text） | 无 | ✅ 白捡：引擎自己的 SenseVoice 听写就能把参考录音转写成底稿，用户不用打字 |
| 客户端音色 UI | 设置 › 语音播报：CosyVoice3 5 音色 + kokoro 103 可自定义 | ✅ 结构已有（分组列表、试听、删除），加「我的克隆」分组 |

## 三、原理（CosyVoice3 zero-shot 克隆）

```
参考录音(8~15s) ──┬─ 16kHz ──> speech_tokenizer.onnx ──> 语音 token 序列
                  │            （前端，ONNX Runtime，Friday.Powers 裁掉了这块）
                  ├─ 24kHz ──> campplus.onnx ──> 说话人向量
底稿文字（参考录音说了什么，SenseVoice 自动转写可得）
                  └────────────> 合成 prompt_speech.gguf（~100KB，含 CRC32）
                                        │
                                        ▼  cosyvoice_prompt_init_from_prompt_speech + tts_context_new
目标文字 ───────────────────────────> CosyVoice3 LLM+Flow+HiFT ──> 用那个声音说话
```

- 上游 API 全部现成：`cosyvoice_frontend_load_from_files(speech_tokenizer, campplus)`、
  `cosyvoice_frontend_prompt_speech_direct(ctx, 16k, 24k, prompt_text)`（直接喂浮点，
  不用文件解码）、`cosyvoice_prompt_speech_save_to_file`；CLI 等价物
  `cosyvoice-cli --frontend-only --prompt-audio ref.wav --prompt-text T --prompt-speech-output v.gguf`。
- zero-shot 模式**需要底稿**（上游文档明确）；底稿错了相似度会掉，所以用 SenseVoice
  转写 + 允许用户改正。
- 每个音色一个 tts context（加载的 5 个内置音色各占一份）；克隆音色同样。

## 四、总体设计

```
┌─ friday-desktop-work（客户端）──────────────────────────────────────────┐
│ 设置 › 语音播报 › 「克隆我的声音」向导                                   │
│   ① 说明+选择底稿（默认给一段固定文本，可自定义）                        │
│   ② 录音（getUserMedia，Chromium AGC，存 16k PCM WAV；也支持选现有文件） │
│   ③ SenseVoice 自动转写录音 → 底稿（用户可改正）                        │
│   ④ voice:clone IPC → 主进程 → POST /v1/voice/clone                    │
│   ⑤ 试听（用新音色念固定样句）→ 满意 → 命名保存；不满意 → 重录            │
│ 音色列表：内置 5 种 + 「我的克隆」分组（试听/删除/重新克隆）              │
└──────────────────────────────┬─────────────────────────────────────────┘
                               │ WebSocket / HTTP（同引擎同进程，127.0.0.1+token）
┌─ friday-voice v0.5.0（引擎）─▼──────────────────────────────────────────┐
│ POST /v1/voice/clone（multipart: file(PCM/WAV) + text + name）           │
│   → 前端(ORT)：16k+24k 重采样 → tokenizer+campplus → prompt_speech      │
│   → 存 --user-voices DIR/<name>.gguf + Synthesizer 热注册（加锁）        │
│   → 返回 {voice, similarity?}；GET /v1/voices 分组列出内置/用户音色      │
│ friday-voice clone REF.wav --prompt-text T --name N（CLI 一次性，同逻辑）│
└──────────────────────────────────────────────────────────────────────────┘
```

**存放**：用户音色存客户端 userData（`voice-power/user-voices/*.gguf`），serve 启动加
`--user-voices DIR`。引擎目录（voices/）保持只读的系统资产，升级引擎不丢用户音色。

**下载策略**：speech_tokenizer.onnx（约几十 MB，确切大小见「待确认」）和
campplus.onnx（28MB）只在用户第一次点「克隆我的声音」时下载（沿用现有 Asset 下载器、
sha256 校验、hf-mirror 候选源）；不做克隆的用户不多花一分磁盘。

## 五、引擎改造（Friday.Powers，voice-v0.5.0）

1. **CMake 恢复前端**：不再 REMOVE `cosyvoice-frontend.cpp`；引入 ONNX Runtime
   （上游 CMake 支持 `ORT_PREBUILT_DIR`，CI 脚本 build-windows.ps1 下载预编译包）。
   现固定上游 commit 6743f9299f4a9cecd05b8f7a2ad5a45a65cf98b1，前端代码就在其中。
2. **Synthesizer**：加 `addVoice(path)` / `removeVoice(name)`（持 m_mutex 建tett context，
   失败回滚并报错）；`load()` 同时扫 `--voices` 和 `--user-voices` 两个目录；voices()
   标记来源分组。
3. **Server**：
   - `POST /v1/voice/clone`：multipart（file、text、name）；miniaudio 解码/重采样到
     16k+24k（miniaudio 解 WAV/MP3/FLAC；客户端录音直接给 16k PCM 最省事）；产出
     gguf 落盘 user-voices + 热注册；返回音色名。名字冲突 → 409。
   - `GET /v1/voices`、`DELETE /v1/voice/<name>`（只许删 user 目录里的）。
   - 前端模型惰性加载：第一次 clone 才加载 ORT session，不用克隆的 serve 不占内存。
   - `/v1/info` capabilities 加 `voiceClone`；ready.voices 带分组。
4. **CLI**：`friday-voice clone`（参数同上，调试和 CI 冒烟用）。
5. **power.json** 版本 0.5.0 + capability；CI 出 Windows（Vulkan）/macOS（Metal）包。
6. **协议文档** voice-protocol.md 补「音色克隆」一节。

## 六、客户端改造（friday-desktop-work）

1. `CosyVoiceService`：POWER_VERSION → 0.5.0（资产 URL 换 voice-v0.5.0）；资产加
   `speech_tokenizer.onnx` / `campplus.onnx`（`ServeNeed.forClone`，首次克隆才下载）；
   serve 参数加 `--user-voices`；IPC：`voice:clone`（audio+text+name）、
   `voice:user-voices`（列表）、`voice:delete-user-voice`。
2. 克隆向导 UI（SettingsWindow 语音播报 tab 加入口）：流程见上图；录音复用
   speechInput 的采集（16k、AGC），存临时 PCM；底稿默认固定文本
   「你好，这是我的声音。平时就用这样的语气跟助手说话，自然一点就好。」（10 秒左右）。
3. 音色菜单：CosyVoice3 分组下加「我的克隆」（自定义音色里已有删除/试听交互可照抄）。
4. 隐私：录音提取完默认删原始录音（只留 ~100KB 的 gguf；提示里写明），全程本地。

## 七、录音规范（向导里给用户看的）

- 安静环境、离麦 20–30cm、用平时说话的语气和音量；
- 8–15 秒为宜（太短像谁不太稳，太长预填充变慢、收益递减）；上限 30 秒；
- 别用变声/带 BGM 的素材；底稿转写改正确再提取。

## 八、测试与验收

1. **客观指标（自动）**：用引擎现成的 campplus 声纹，算「克隆音色合成结果 vs 参考
   录音」的余弦相似度；矩阵：录音时长（5/10/20/30s）× 录音条件（干净/轻噪）。
   参考：同人 3s 句一般 0.7–0.98，不同人 <0.3（协议文档给的量级）。
2. **主观**：同一句「今天下午三点在会议室讨论新版发布计划」用克隆音色 vs 内置音色
   念，本人盲听确认像不像；中英混一句看英文词的口音保持。
3. **回归**：不克隆时 serve 冷启动、播报 RTF/首块不回归（前端惰性加载保证）；
   克隆音色后播报首块、RTF 与内置音色同量级；听写链路不受影响。
4. **资源**：每加一个克隆音色的显存增量（RTX 2060 6GB 上限内能挂几个 tts context；
   超过就 LRU 卸载闲置 context——留作 v0.5.0 的后手，不做过度设计）。
5. **持久**：serve 重启/应用升级后用户音色仍在、能删除。

## 九、风险与对策

| 风险 | 对策 |
|---|---|
| ONNX Runtime 依赖：二进制 +10–20MB/平台，符号/静态链问题 | 跟上游 CI 同款预编译包；只在 clone 路径加载；出问题退到「ONNX 只编进 clone 子命令」的裁法 |
| speech_tokenizer.onnx 确切文件名/大小/下载源未最终确认（HF 今天网络不通） | 实施第一步就确认（上游 frontend 代码 + ModelScope FunAudioLLM 模型库）；下载器已有 hf-mirror 候选机制 |
| 每音色 tts context 占显存 | 实测；必要时惰性建 context / LRU 卸载 |
| 克隆相似度不达预期（16k 麦克风、零样本上限） | 向导里给录音规范；客观指标卡阈值（如相似度 ≥0.6 才让保存，否则建议重录）；instruct 模式补语气 |
| 伦理/合规 | UI 明示「只克隆你自己的声音」；本地处理不上传；默认不留原始录音 |
